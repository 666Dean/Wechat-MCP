# 功能状态、未完成部分与未知事项

最后审查：2026-10-10。**这是实验性原型，不能作为已上线的全天微信代理。**

## 如何理解证据

- **已实现并模拟验证**：代码存在，自动测试使用 MockAdapter 或模拟 MCP 服务。
- **已实现，未实机验证**：有真实适配代码，但没有实际微信收发证据。
- **未实现**：代码当前不提供该能力。
- **未知**：需要版本、设备、账号或真实场景实验才能判断。未知不能当作兼容承诺。

| 能力 | 现状 | 证据与边界 |

| 更改名单 | 已实现并模拟验证 | MCP 写入默认关闭，启动参数显式开放后当前进程立即生效；CLI/脚本改动在服务下一次工具调用加载 |
| 管理权限限制 | 已实现并模拟验证 | 工具注册和 Bridge 写入双重限制；配置热加载不能开启；不认证所有者，不能限制客户端的其他文件/shell 工具 |

| 发前目标核对 | 已实现，未实机验证 | 名称和 friend 类型核对；核对与发送之间仍存在手动切换竞态 |
| 测试与发布说明 | 已完成本地检查 | 34 项模拟规则、配置、进程和协议测试通过；本轮 Windows/Python 3.14.7，仅模拟后端；安装要求仍为 3.12 x64；无远程 CI 证据 |

## 明确未完成

1. **所有好友后台监听**：不能发现或持续监听未打开的会话，也不会自动遍历好友列表。
2. **全天自动回复**：没有常驻 AI 模型调用、事件调度、模型 API 集成或可靠服务管理器。
3. **关机后继续运行**：没有云端执行环境。现有 Windows UI 适配器需要运行中的设备和微信。
4. **对话理解**：不会可靠识别一句话是对主人还是对 Codex 说；基于提示让 AI 判断。
5. **实时检索与个人知识库**：没有联网知识验证、可分享资料白名单或知识库模块。
6. **附件及群聊**：不处理图片、语音、文件、群消息、撤回、转发和历史补录。
7. **独立身份认证**：已提供启动时管理能力开关，但没有账户认证或所有者签名；显式开放后的调用来源仍依赖可信 MCP 客户端。见 [认证说明](AUTHENTICATION.md)。
8. **硬性语义限制**：不替主人承诺、不跨聊天披露资料等属于模型提示，尚非程序级语义保护。
9. **运行维护**：没有完整启动自检、健康恢复、数据库迁移、状态清理界面及长期监控。
10. **GUI 和安装包**：没有图形设置页、可执行文件签名或免 Python 安装包。

## 未知及已知薄弱点

| 项目 | 当前知道什么 | 仍需验证什么 |
|---|---|---|
| 微信具体版本 | 固定 wxauto4 41.1.7；发布说明曾声明 4.1.8 | 使用者当前版本的 UI 控件与收发是否兼容 |
| 可见消息范围 | GetAllMessage 依赖可见 UI | 滚动、折叠、长消息、表情、引用能否完整读取 |
| UI 消息 ID | 可能随切换变化 | 无交集时重新基线会漏收；部分 ID 重用也可能误判，不承诺全局去重 |
| 本人同时输入 | 未提供输入框草稿检测或锁定 | AI 发送是否会混入草稿、打断输入或发给切换后的对象 |
| 系统环境 | 需要 Windows 桌面客户端 | 锁屏、睡眠、缩放、多显示器、语言、远程桌面、最小化行为 |
| 登录状态 | 状态接口调用 IsOnline | 断线、重登录、微信升级后的恢复和状态一致性 |
| 重启 | 回复状态持久，基线只在内存 | 已处理队列过期和 sending 转 unknown；重启期间漏收、UI ID 冲突仍未解决 |
| 多实例 | 同一规范数据库路径已有跨进程锁 | 不同数据库指向同一账号、硬链接别名及网络文件系统尚未覆盖或验证 |
| 配置并发 | 合作进程通过独立锁串行读写并原子替换 | 完整名单最后一次成功写入生效；编辑器不遵循锁，没有版本冲突提示 |
| 多个账号 | 未绑定账号唯一标识 | 更换登录微信后旧状态可能混用，需要手动换状态文件 |
| 联系人身份 | 只核对显示的名称 | 备注重名或改名；未根据稳定 ID 建立身份映射 |
| 第三方依赖 | wxauto4 固定发布版本，部分是二进制模块 | 没有审计 DLL 内部行为；关闭配置中的 telemetry 不等于独立网络审计 |
| 平台规则及账号影响 | 第三方客户端自动化，非官方代回好友接口 | 是否受平台限制、限制阈值、长期稳定性均无保证 |
| 本地隐私 | 数据库是本地明文；gitignore 排除运行数据 | 没有加密、自动留存清理或对任意 state_file 路径的发布审计 |

## 下一步验证顺序

1. 使用本人明确授权的测试聊天，保持预览，记录 OS、Python、微信和依赖具体版本。
2. 确认当前聊天名称、消息来源及文本；切换、滚动、重开窗口，记录漏收或误判。
3. 增加草稿检测和发前再次核对；验证账号级互斥需求，再做显式授权的少量发送测试。
4. 在稳定身份与事件读取基础上开发全好友监听和常驻模型调度。
5. 完成异常恢复、权限与数据留存控制后，再讨论无人值守部署。

## 功能承诺边界

将代码上传 GitHub、单元测试通过或 MCP 握手成功，都不能证明微信实机联通。
本仓库不承诺全好友覆盖、24 小时可用、零漏收、零误发或账号不会受限制。
首次发送及其他真实测试必须基于具体使用者的授权；公开 CI 只用模拟数据。
