# Windows 一次性设备验收入口

本文件描述软件入口，不是执行设备测试的授权或验收结论。本轮仅用合成数据、软件测试签名、临时文件、真实 Guard/账本及离屏 Qt 验证，没有运行真实验收计划。

## 与正式服务的次序

1. 完成 [Windows 全项目软件清单](WINDOWS_CODE_COMPLETION.md)、相关构建/离线回归和冻结分发检查。
2. 本人另行决定具体设备实验，独立审查者核对该软件审计与当前 Windows 构建/配置后签署一份有限计划。产品不保存审查者私钥，也不自动签署计划。
3. 本人停止正式服务，选择计划，显式进入“一次性设备验收”；UAC 暂存到固定数据目录，并只调用 `--qualify-service`。
4. 固定 System host 核对实际保护安装、MAC 构建 pin、既有 owner、公钥清单、配置、导航与 OS。独立密封序列检查永久认领该计划，随后固定 owner 交互进程展示精确计划并请求既有 Hello 签名。取消也消耗计划，不自动重试或创建新密钥。
5. 仅执行一个场景，结束即撤销本次全部 TaskContract，停止 helper 接入服务并保留不确定尝试。结果只返回聚合事实，不生成 `device/pass` 材料。
6. 由审查者另行保管、核对真实原始记录，并按 [准入材料格式](WINDOWS_NAVIGATION_ADMISSION.md) 签署设备材料。普通 `--service` 仍要求完整设备准入，缺材料不回退到验收入口。

安装、首次 Hello 与凭据迁移已有各自独立固定入口；这些入口不要求事先宣称设备通过，也不授予运行期任务。验收入口解决的是后续读取、隔离来源推理及发送证据与正式服务准入之间的次序。

## 计划格式

文件是 P-256/SHA-256 DER 签名封套，恰有 `body`、`key_id`、`signature`。密钥来自已经由安装清单和本人配置固定的审查者清单，不接受文件内附公钥。签名覆盖 `axr.aet.canonical(body)`。

body 恰含以下字段；完整封套最大 20,000 字节：

| 字段 | 约束 |
| --- | --- |
| `version` | 整数 2 |
| `product` | `wechat-codex-mcp/windows/qualification`；与正式准入材料的 product 不同 |
| `sequence` | 1 至 2^53−1 的严格递增整数；独立 authority 秘密库的密封高水位防止删除/替换计划文件后重放 |
| `subject` | 与本机未签署材料请求中的 subject 精确一致，绑定 Windows 构建、配置、owner 公钥、导航和 OS |
| `created`、`expires` | 有限 Unix 时间；不接受未来签发或过期，整个有效期最多 600 秒 |
| `nonce` | 64 字符小写 hex，区分本次有限计划 |
| `software_audit` | 恰有 `complete=true` 和全项目软件审计记录的 `record_sha256`；是可信审查者声明，产品不伪造审计记录 |
| `plan` | 恰有 `scenario`、`target`、`parking`、`text`、`since` |

`target` 与 `parking` 必须是两个不同的已配置、已在本人目录中绑定的稳定私聊 ID，不接受群、公众号或系统会话。`since` 是 0 至 2^63−1 的整数。所有场景均不能导入 helper、端点、工具、凭据、任意模块或命令。

此有限入口的 ID 与发送正文不接受换行或其他控制字符。正常回复事务原有文本能力不因本实验入口改变。

| scenario | 实际边界 |
| --- | --- |
| `metadata` | 仅原有就绪检查的布尔元数据，不导航、读正文、推理或发送；text 必须为空 |
| `read` | 只读 target 从 since 起的一页，最多 6 条，不追页，不向模型或桌面返回正文；text 必须为空 |
| `source` | 同一页进入既有单来源 AppContainer 推理，不继承父历史或工具，不发送模型回复；text 必须为空 |
| `send` | 本人和审查者签署的唯一精确 text，最多 16,000 UTF-8 字节，保留署名前缀要求；固定 target/parking，保留草稿，不允许覆盖，仅在前台且空闲时执行一次完整回复事务 |

`source` 不绕过独立人工审批开关：开关开启时，读取后的脱敏精确记录经原生认证 owner 管道展示，再取得一次 Hello 签名，取消则不调用模型。记录和摘要同时绑定在挑战中，内容改变会拒绝；不通过明文临时正文文件传递。关闭开关时仍受本次精确来源、页数、固定模型目的地、有效期及初始本人签名约束。

## 运行与停止边界

`QualificationSession` 复用固定文件、信任根、subject 及双时钟期限检查，但只能读取单独的 `windows-qualification.json`；它不能成为正常 `RuntimeAdmission` 的设备材料。程序内没有切换正式 gate 的布尔值或正常启动失败后的降级路径。

验收 helper 接入只接受真实已登记 handler 的 preflight、claim 和 receipt。普通客户端、owner 控制、两套 MCP API、新 Authorize 请求均拒绝；后台调度线程从不启动，不执行旧队列。每个动作仍走真实 Guard、TaskContract、完整性检查、精确意图和固定原生执行器，另外核对目标、操作、来源及目的地是否在计划内。

墙钟或单调时钟到期/倒退、固定文件变化、取消、响应丢失或异常都不续期、不恢复旧授权。认领前失败不能生成执行许可；认领后的 Unknown 不改为成功、不重发。发送仍保留精确缓存/搜索见证、完整输入比较、永久尝试及独立数据库观察，数据库观察不证明对端送达。

维护操作完成后恢复 SCM 的普通 `--service` 命令，但不启动它。固定结果文件 `windows-qualification-result.json` 只含本次计划摘要、聚合元数据和机器错误码；桌面核对摘要，不接受旧结果，不把 Recorded 当作产品准入。该文件是运行状态，不是自动导出的证据包。

本入口覆盖有限链路的观察，不自动完成九类人工审查、对抗性实验、跨账号/多日稳定性或发布验收。那些记录仍需实际设备阶段单独取得。
