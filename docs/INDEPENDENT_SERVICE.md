向导拒绝覆盖已有部署，不把开发者本人的安装包或账号数据带给其他用户。

公开包不再分发供应方 Codex 程序。本机安装仅复制并验证使用者已有的签名 CLI
与公开 CA 到受保护固定路径，保留原签名，并固定摘要；不复制 Codex 登录内容。

## 固定模型组件与启动检查

macOS 本地打包要求提供方摘要与显式指定的源映像一致，再复制完整签名 Codex CLI
App 到 Authority 资源目录，保留原签名。服务调用受保护副本，不随外部应用更新；
仍逐次校验程序和信任包摘要，继续使用单来源空工作区与原有 OS 隔离。
登录文件只由固定传输读取，不复制到包中或进入提示词。仓库不包含第三方可执行程序。

停止后的安装/构建更新只容许该固定程序路径与 SHA-256 改变，其他部署字段不变；
硬件签名绑定新的配置与构建，再保存经批准的提供方配置。取消不恢复旧任务或权限。
普通开启也先检查程序、登录文件和信任包，再请求范围签名；状态检查按文件状态缓存。

桌面对话目录通过 OpenAI 的公开 [App Server](https://learn.chatgpt.com/docs/app-server)
读取，包含 `vscode` 等交互来源并保留游标。目录浏览不改变绑定或授权；现有范围
生效时可浏览，保存新绑定仍需先停止并二次确认。旧 MCP 进程在升级后可能需要客户端
重新连接；App 的 Owner 连接与 Codex 中缓存的 MCP 连接分别核对。

  CA 摘要或提供方构建变化即拒绝使用。
- macOS 打包工具复制 Python、Zstd、SQLCipher 和原生依赖闭包，重写加载路径，

## macOS 操作路由与当前验收

原生 `AXR MCP` 仅接受固定 `--mcp` 入口，在 Python 和请求解析前应用 OS 沙箱；
初始化、工具发现与状态不创建执行租约。真正的数据和副作用请求发送到独立
Authority，角色来自受保护构建与实际 PID/birth，不使用持久 bearer。

Owner 通过硬件用户在场签名批准精确范围、目标、模型目的地、时限和次数。
可设置直至停止的站立授权，但每个派生 TaskContract 最长一小时、最多十万次；
重启不恢复站立权限。设置中的停止无需再次认证，并使当前推理和原生提交失效。
普通读取与向 MCP / 来源模型披露分别检查；不同来源使用全新隔离模型进程。

服务内调度处理新入站、类型化草稿、自动选聊、精确输入、单次提交和独立数据库
核对。MCP 主动发送采用稳定请求号；更换正文被拒绝，更换请求号也不能重发已知
不确定正文。中断任务保留 Unknown。人工草稿使用独立面板，不自动提交。
本地任务缓存容量有限，大范围轮询延迟与全天稳定性尚未验证。

写入帮助进程在当前会话中通过原生编辑命令状态检查实时输入，不能从旧缓存推断
输入是否为空。默认保护真实输入；所有者可在设置中批准强制覆盖，该选择进入签名
范围及密封的写入绑定。未知附件/窗口仍停止；此设置不放宽身份、精确文本或提交
回执校验。实现与设备验收分别记录，不将新增设置称为已验证的附件自动发送。

首次设置失败后保留进度。已经保存的审批收据由原生 Root 密钥认证；仅当部署
配置、OS 用户、收据与硬件身份一致，bootstrap 尚未生效、账本无权限/任务/审计
事件、受保护审计锚仍为零时，才能接续同一初始化，**无需重复所有者认证**。
任何历史执行记录、非零审计锚、配置或收据校验失败均拒绝接续；不恢复旧权限。
已迁移的原生凭据优先重新校验并复用，不重复访问旧 Keychain 条目。

配置写入前检查大小，读写预算一致；全部目标的站立审批按来源派生有限小任务，
不会把完整联系人目录塞进每次执行证明。开启服务先检查实际数据库访问和辅助
功能权限，通过后才请求一次范围签名；同范围内不逐次认证，停止无需认证。
应用区分缺少系统权限、服务断开和审批过期，避免用重复认证掩盖前置问题。
凭据引用采用固定摘要名，原始密钥始终留在原生边界。

当前证据包括实际无重复认证的初始化接续、原生凭据迁移、独立服务连接、MCP
初始化/六项工具发现/消息分页、Secure Enclave 设备绑定重建及签名，以及加密
合成库与调度/停止/幂等回归。两个系统权限已由实际服务核验，范围签名成功；
搜索后直接 Enter 的路径已自动核对稳定会话身份。已有草稿导致测试停止，未覆盖
草稿或重发 Unknown。主动发送、入站自动回复及读回仍待完成新服务验收。
Windows 应用前端/所有者硬件提供方及微信设备验收未完成。

原生帮助进程在本次 birth 内复用受认证连接；每帧仍校验 OS 对端、方向 MAC、
序列和 epoch。已经认领的五秒许可可在逐键检查时本地验签，不能本地签发或续期。
连接失败后不重连、不重放；最终发送重新向服务认领并复核撤权和精确输入。
搜索框不再通过全选复制核对查询，因为该操作会影响微信结果选择；查询的剪贴板
epoch 与密封意图一致，并在任何草稿插入前核对新鲜 SearchRecent 的唯一稳定 ID。

Qt 应用的核心连接、授权、停止与人工草稿已接入独立 Owner。部分简报、附件、
会话绑定和工作流页面仍需要迁移，不将开发启动器或已连接状态称为完整发行。

整合远端更新后本机全量回归 572 项发现、511 项执行通过、61 项按平台或可选条件
跳过；参考原生重建后 CTest 2/2 通过，正式宿主/前端/消费者构建通过。新 GUI 权限
前置状态和配置回归 11 项执行通过、1 项平台跳过；真实 Qt 权限状态来自服务。

硬件表示采用 [Apple CryptoKit API](https://developer.apple.com/documentation/cryptokit/secureenclave/p256/signing/privatekey/datarepresentation)，

## 本机部署流程

1. 构建并校验独立签名包，使用 `scripts/install_authority_macos.py --package <package>`
   完成系统管理员确认。只安装 Authority、Owner 和 MCP；开发验证工具不安装。
2. 在本机交互终端运行固定 Authority 的 `--initialize-owner`。独立 Owner 对配置
   摘要和新随机挑战进行硬件在场签名；原生迁移已有凭据并建立新账本，不恢复权限。
   中途失败时先检查已保存进度；符合空事务条件的原审批自动接续，不循环弹窗。
3. 运行 `scripts/register_authority_service.py` 注册用户级服务。在 Qt 设置中连接
   Codex、选择目标和期限后批准权限；服务进程不依赖 MCP 客户端保活。

## 保留现有状态的更新

## 变化调度与本人任务

全私聊范围使用固定账号元数据预筛，只查询更新的来源；没有变更时降低唤醒频率。
MCP 状态只报告范围计数，目录和消息由显式工具查询。正式打包拒绝无优化构建；
编译优化不减少密码学、身份、完整性或单次提交检查。

本人任务是单独批准的权限，不影响普通来源隔离。仅本人实际 ID 的 `/agent ` 新文字
能进入绑定 Codex 对话，等待受信任的空闲事件，并先在 Root 记录单次披露。客户端
通过公开 App Server resume/turn 协议执行，收紧为 workspace-write/untrusted 审批；
不增加工具、权限或自动放行规则。具体取舍及未验收项见
[本人任务说明](OWNER_AGENT_AND_EFFICIENCY.md)。
