# MCP 自动回复与 Codex 对话绑定

WeChat MCP Desktop 在 macOS 原版微信主窗口上提供所有者授权的文字自动回复。
读取、模型披露、草稿、导航、发送和数据库观察分别受 AXR 检查；MCP 不提供授权签发接口。
默认仍为人工提交。Windows 保留读取、草稿和人工回复，不声明自动发送资格。

## 设置与使用

1. 安装 Qt Desktop、AXR 原生依赖及已构建的 Mac 导航 Helper，保持原版微信登录，
   Mac 已解锁且主窗口可显示。Broker 启动时提供 `--helper <axr-helper>` 和
   `--chat-helper <wechat-chat-navigation-experimental>`，桌面可从标准构建目录发现后者。
2. 在设置中选择已有 Codex 对话，保存助理人设、回复风格及是否显示 AI 署名。
   支持导入 UTF-8 人设文本（最多 12KB），风格最多 4KB。偏好加密保存在本机。
   更换对话或偏好前先停止当前会话，避免运行中悄然改变披露目的地或回复规则。
3. 配置 Codex 生命周期连接，并在 Codex `/hooks` 中亲自审核和信任四项定义。
   App 不写入信任记录；Hook 仅转发会话、轮次和忙闲事件，不转发提示词或聊天正文。
4. 选择至少两个已绑定私聊（另一个用于草稿缓存切换），或选择“全部可用私聊”。
   全部范围包含本账号已校验本地消息分库中的私聊及后续新核验私聊，排除群、
   公众号、文件传输助手和已识别的系统会话；不是任意账号或服务器完整历史权限。
5. 选择时长和回复次数，二者均支持“不限”。无限模式要求绑定 Codex 对话。
   核对目标、模型披露和前台操作说明，通过本机系统认证后才开启。
6. 新入站消息进入本地任务队列。当前 Codex 用户任务执行中时只排队；完成后继续
   同一 Agent 循环，空闲时用官方 `codex exec resume` 恢复绑定对话。
   不向输入框塞命令，不模拟 Command+Enter，不把进行中的开发任务当成空闲。
7. Codex 通过 MCP 读取精确批次并生成草稿，`wechat_finish_task` 交给本地控制器
   自动选聊、单次提交及独立数据库核对，无需单独运行计划 CLI 或人工开独立窗口。
8. 随时在设置点“停止自动回复”。到期、额度耗尽、发送不确定且无记录或校验失败
   会停止并撤权。退出或重启 Broker 不恢复授权，必须由本人重新开启。
   人工回复面板独立保留，可另行授权读取与人工处理。

## 忙闲交接与新增授权

对话目录使用官方 App Server 元数据接口；侧车返回的 `notLoaded` 不能证明桌面空闲。
只有受信任的 `SessionStart`、`UserPromptSubmit`、`Stop`、`Interrupt` 事件推进交接。
未知状态保持排队，中断保持暂停；用户新任务优先，回复进程收到终止，不自动重发。
生命周期事件通过独立元数据通道确认，不等待数据库/GUI 锁；排队快照由监听调度维护。
Hook 的审核方式见 [Codex 官方文档](https://learn.chatgpt.com/docs/hooks)。

MCP 新增 `wechat_assistant_profile`、`wechat_request_authorization` 和
`wechat_authorization_status`。Agent 可以依据主人命令申请新增联系人，任务遇到
范围外目标时说明缺失权限并提出申请；申请本身没有权限。用户在“待授权”或设置
核对精确目标、用途和披露目的地，通过 OS 认证及唯一身份验证后才加入范围，
Agent 查询批准状态后继续。聊天里的指令不能改变授权，也不能代主人批准申请。
没有活动自动回复会话时，新增目标只获短时本地读取/草稿权限，不开启自动发送。

## 执行与安全

- 只对开启后新入站文字的 `incoming_reply` 任务自动批准。显式读取任务、旧消息、
  本机出站、群聊和范围外资源不能自动触发发送。每批最多 6 条/24KB。
- “不限”是当前所有者会话的时间/数量选项。读取仍使用至多 5 分钟/400 次的子授权，
  发送仍是精确目标、正文、来源绑定的短时单次凭据，停止立即撤销，不发永久发送令牌。
- 忙碌队列只加密保存消息引用和时间边界，最多 1000 项、24 小时；取任务时重新读取
  并精确核对引用。正文上下文最长 5 分钟。单批预算、来源保守传播和 SDK 来源上限
  继续生效；超限/缺失/变化会安全停止，不因“无限”绕过资源与隐私边界。
- 双时钟、策略版本、配置与 Helper 摘要每阶段检查。历史披露来源不能通过省略
  context_id 清除；范围外来源阻止发送。源分库变化时有界轮询，连续分页不依赖后续写入。
- 复用 [主窗口发送算法](AUTONOMOUS_CHAT_PLAN.md)：运行账号打开文件见证、
  新鲜搜索记录、唯一精确草稿缓存及消费转换、两次输入比较与原生精确证明。
  不使用 OCR、注入、客户端修改或捕获保护绕过。
- 任何输入前持久化认领任务；提交前链接主 Journal。相同任务即使重启或崩溃也不重放。
  不同新任务可以有相同回复文本，独立基线排除历史 server_id，不把旧记录当成新发出。
- 原生键盘回执保持 `Unknown`。数据库唯一完整文本、本人 sender、出站方向及非零
  server_id 是独立观察，`database_record_observed=true` 不修改原回执，
  `delivery_confirmed` 始终 false。没有精确记录便停止，不发送第二条。
- Stop 先取消并撤销原生凭据，不等待 GUI 任务锁。已经提交的外部副作用不能撤回。
  所有者控制仅在本机独立通道，默认数据和尝试记录留本地，正文加密；没有遥测。
- 当前用户的无限 shell/file 权限不在本地 bearer token 的隔离承诺内。
  本地所有者信任与模型正文披露仍是不同边界，不能把 MCP 申请当成授权。

## 实测与初代边界

2026-10-16：正式 MCP 会话中，两条不同的新入站消息分别完成 Codex 草稿、主窗口
自主选聊、一次提交及各一条精确数据库发出记录；无人复制、按发送或开独立窗口。
停止后有效权限为零，重复查询两个任务均返回原回执且未重发，审计正常。
该实测为有限会话；同对话长期恢复、无限/全私聊、多日运行另行验收，不由两次发送外推。

发送会激活微信，后台监听和 Agent 等待可以运行；锁屏、无焦点后台写入、任意微信
版本和多日稳定性不在已证明范围。已有输入不覆盖；不匹配时可能留下追加的未发送
草稿，应由主人处理。产品仍需本机 Python/Qt 运行时，非签名安装包。

初代仅自动生成和提交文字回复；附件保留独立本地读取能力，不自动发文件。
支付、朋友圈、小程序、账号管理、群管理及聊天要求的任意外部执行均不在范围。
用户在 Codex 的主动命令可读取、总结、生成草稿和申请目标授权；自动发送入口仍
限获准的新入站回复，不能借此任意跨联系人发信。
