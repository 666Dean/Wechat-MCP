# 全账号内容复核与自动回复草稿

本功能用于主人明确授权的当前微信账号内容复核。目标是分页读取实际可取得的本地记录，生成按会话的内容总结、任务清单及覆盖报告；发送由人提交。账号目录、微信业务与 MCP 位于 SDK 外，通用授权与 AX 结构检查位于 `AXR/`。

## 所有者会话

在本机解锁状态的交互终端运行：

```sh
python -m axr_integration.owner_review --state OWNER_STATE --helper AXR_HELPER --ttl 3600 --pages 8192
```

先显示范围，再进行 OS 身份认证。使用已有 Keychain/凭据库缓存进行 salt/HMAC 复核；只读验证账号目录与本人联系人，按 Name2Id 和实际 Msg 表名唯一映射稳定会话 ID。纳入本地可识别的私聊、本人、群聊及公共/服务会话，不把同名昵称当身份。不会重新登录、取钥、重签客户端、关闭 SIP 或启动截图捕获。

最多 4096 个表映射会话，配置仍受 SDK 元数据大小上限约束；过大的策略在赋权前拒绝并要求分区。缺失密钥的消息分库和无法映射的表独立计数，不伪装成空对话或已完整读取。目录与分页固定相同时间上界；活跃客户端的跨分库查询不是原子快照，也不表示服务器历史已同步完整。

一次身份认证建立最长一小时的独立 review principal。最多 8192 页，全会话/所有读取工具共用持久预算，每页最多 6 条记录，模型正文每批最多 24KB、每条文本最多 4000 字节；截断明确返回标记。数据仍经 AET 只读、独立精确单次披露批准，不给 review 身份微信发送或修改联系人权限。默认监听关闭，避免对全目录每五秒无差别扫描。

## 实际 MCP 分页

同一 state 只运行一个 broker。示例交互客户端：

```sh
python scripts/review_wechat.py --state OWNER_STATE --show-content
```

stdin 命令为单行 JSON：

```json
{"op":"catalog"}
{"op":"page","index":0}
{"op":"ack","summary":"根据这一页实际内容生成的摘要"}
{"op":"quit"}
```

客户端真正连接 `server.py --manual-replies` stdio MCP。目录分页最多 100 个绑定；读取、精确批准与正文取得分别使用 MCP 工具。只有 `body_disclosed=true` 才能处理正文。`--show-content` 明确将获准内容传给调用者，不保存原始消息/JSONL 日志；未加该选项只显示元数据。不得把私聊正文写入公开终端日志或 Git。

`wechat_request_task` 现在支持同过滤条件的 opaque cursor/时间上界；预算对 `wechat_read_context` 同样生效，不能借另一入口绕过。记录 `scanned`、文本数、`has_more` 和 `budget_truncated`；无文本但仍有下一页时继续。按会话读至 EOF，并核对目录记录数与扫描数，失败/截断/缺失部分明确报告。图片、语音、视频、卡片等未解码的记录只能计数，不能根据计数猜内容。

`wechat_acknowledge_review` 必须在精确披露 Completed 后重验源授权，只保存有界加密摘要和源上下文摘要，移除已处理收件箱条目。摘要受当前策略版本和会话 TTL 限制；它不是发送、执行任务或语义正确性的证明。停止/到期撤权；配置未被其他所有者修改时恢复先前绑定并关闭三个控制开关。

## 同一认证内测试自动草稿

```sh
python -m axr_integration.owner_review --state OWNER_STATE --helper AXR_HELPER --ttl 3600 --pages 8192 --draft-contact EXACT_CONTACT_LABEL --draft-self --phase-file PRIVATE_PHASE_FILE
```

私有控制文件在开始时必须不存在；联系人和本人选项在本次所有者调用中固定。内容复核结束后先退出 review broker，再由可信本地所有者控制面把该文件写为 `reply`，启动全新的临时 Codex worker。MCP 不暴露阶段控制、issuer 或 owner 工具；模型的只读 sandbox 无法写此文件，微信内容也不能改变固定联系人或权限。

回复阶段在原始总时限内重新核对所选稳定 ID，创建全新 principal；旧身份的披露 taint 保留。它仅对已选联系人签发读取/草稿额度与最多 12 批精确披露批准。启用 `all_incoming`：不需测试关键词，仍过滤出站、重复和过期事件。普通 CLI 也可用 `owner_codex session --all-incoming`；默认值仍为 false，字符串不能变成真值。

原有 Codex worker 自动完成入站任务和回复草稿，本地面板核对复制，用户手动提交；可再经独立 WCDB 只读观察完整匹配记录。原生主动发送需运行账号、收件人、请求 ABI/生命周期及实际提交资格；尚未通过的路径保持关闭。

## 本轮证据

2026-10-12：新增回归验证目录 SQL 的私聊/群聊/公共会话映射与未知表计数、共享预算/快照、精确披露前拒绝摘要、加密存储、非关键词入站过滤、收尾恢复及固定联系人阶段切换。通用 Swift 结构遍历新增 PID 校验与 CFHash/CFEqual 循环去重，并拒绝把应用/菜单根当作有效窗口。

本机当前锁屏。旧探测在循环路径中将菜单搜索字段计作 7 个编辑节点；修复后结构为 199 个唯一节点、跳过 1 个循环，聊天标识仍为 0；窗口根未资格。该锁屏观察不能外推解锁状态。合成 Cocoa 控件和全账号真实正文读取仍待解锁后的本轮认证验收，不把前轮两个私聊的成功代替全账号成功。

本轮实际 stdio MCP 握手、工具列表及状态查询成功，注册 23 个工具；当前仍为前轮两个绑定、三个分库，三开关关闭、人工模式、审计有效。这是协议可用性证据，不代表 23 项微信业务均已可操作，也不代表全账号已启用。
