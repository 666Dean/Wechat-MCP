## 已接通的回复事务

`wechat_submit_reply` 只接收本任务已有草稿句柄和授权会话。helper、标签、选择器、停车会话、署名要求及服务地址均来自受保护的所有者配置。签名任务必须同时包含读取、元数据、导航、草稿、最终提交、相关资源/来源和目的地；只有最终发送操作的宽泛任务不能启动该事务。

人工审批开启时，owner 核对包含精确正文、目标、来源及配置摘要的计划后签名；关闭时仍受原有签名任务范围约束。旧待审批计划不会因为后来关闭开关而自动变成已批准。`axr_execute` 排入受控异步任务，`wechat_reply_status` 返回状态和脱敏观察元数据，避免 helper 回连等待当前请求释放同一管道或 authority 锁。

事务按以下固定顺序执行：有界缓存草稿检查（默认要求空，覆盖须本人签署）→ 选目标并核对新鲜搜索 → 暂存且比较草稿 → 切换停车私聊 → 唯一精确缓存见证 → 返回目标并核对消费转换 → 原生精确输入比较 → 数据库基线 → 永久认领尝试 → 单次提交 → 独立数据库观察。每阶段有自己的精确权限和账号执行租约；停止先撤权/取消，再等待子进程。helper 结束后删除精确 PID/birth 登记，避免积累旧实例。

独立观察要求精确全文、本人 sender、出站方向、正整数 server_id、排除基线且只有一条新记录。观察成功不会把原生 Unknown 改成 Completed，不表示对端送达。丢失响应、观察失败、重复记录、撤权和过期均不能触发重发。
