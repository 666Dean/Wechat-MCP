# Mac 原号私聊发送：GitHub 源码复核

## 2026-10-14 单次发送与数据库核对

一个已授权私聊已通过普通键盘路径：Agent 准备新的独立测试文本，两次本地
精确草稿匹配后提交一次，独立数据库查询查到唯一发出记录。没有 OCR、注入
或主人复制/提交。新的认证宿主真实认证成功，窗口前后顺序修正后不再误拒绝。
旧 Unknown 不重试；本人私聊、后台及正式 MCP 自动回复未验收。
实现、严格证明回归与父控制器条件见 [固定窗口实验](PINNED_INPUT_EXPERIMENT.md)。
下方 2026-10-13 结果保留为前一轮历史，不能覆盖今天的有限成功或夸大其范围。

## 2026-10-13 非 OCR 草稿读回实测

指定独立私聊由主人初始化并确认输入框为空，Agent 自动写入一条唯一合成草稿；
未由主人复制或提交。应用级 Computer Use 在后续复制中显示窗口标识变化，Mac
接口也不支持直接按独立窗口 ID 绑定，所以没有按回车。

本地 Swift 验证器随后通过新的 OS 认证，使用公开 AppKit/AX 窗口操作固定进程、
独立窗口实例、精确标题、几何与前台窗口，执行普通键盘复制。实际结果为：
`window_verified=true`、`copy_received=true`、`exact_draft_match=true`。
图片未捕获，正文只在本地比较；剪贴板临时保存在内存中，并按所有权条件恢复。
这证明本机可以非 OCR 读回指定初始化窗口的草稿，不代表 Agent 已发送。
收件人关联的保证仍是主人选择的独立窗口，不能写成已取得原生微信 ID 控件。

一次提交验证器已准备精确 SDK 提交证明、单次权限、进程/窗口/正文复核、独立
数据库读回和持久尝试标记；尚未作为 MCP 后端发布或启用。缺失证明以及篡改
正文、身份、几何的合成请求均在输入前被拒绝。真实提交的认证阶段立即返回
macOS `systemCancel`（-4），没有建立发送权限，也没有执行发送键。

新增主循环认证宿主与可取消窗口正在验收，不能仅凭构建与模拟测试称为系统
取消问题已解决。此前只读认证不授予发送；不自动重试认证或发送，不复用退出
进程的许可。真实发送、指定会话数据库记录核对与后台写入仍未完成。

SDK 另查询焦点控件的角色、所属窗口与可编辑性，不取 Value/Title/Description。
真人聚焦的原版窗口仍没有返回焦点输入节点；独立合成控件可返回可写输入，
正文 getter 调用计数为 0。该元数据不会打开发送入口。

## 发消息专用 Computer Use 的可行范围

按键输入与 OCR 是不同环节。没有可用截图并不必然阻止系统发送键盘事件；
当前缺失的是发送前的可靠目标、焦点和正文见证，不是已经证明系统拒绝一切输入。
不通过“搜索后取第一项”、名称哈希或发后发现错误来替代发前核对。

若获得适用接入依据与真实身份/输入见证，可以沿用现有发送事务而非另造权限通道：

1. 密封原账号、内部收件人 ID、原文和来源，取得本地精确批准。
2. 绑定签名客户端、进程/窗口实例和对应收件人见证；切换账号、窗口重建、焦点或
   目标变化均停止。仅窗口标题、PID 和数据库中的同名联系人不足以完成这个绑定。
3. 单独核对空输入框，使用受限输入动作。剪贴板读回只能在已确认的输入区域进行，
   只在本地比较精确正文，不把整份剪贴板或其他窗口内容交给模型。
4. 最终提交前再次核对目标、正文、焦点、授权和能力，只发送一次。
5. 通过独立读取核对发出记录；失败、超时或证据不足保留 Unknown，不自动重试。

该方案的输入回读思路可以减少 OCR 依赖，但它目前没有补齐本机稳定收件人见证。
尚未实现新的剪贴板发送后端，没有真实发送或后台写入，也不声称自制 Computer Use
已跑通。官方单窗口透明帧与 AX 控件缺失仍按既有失败安全规则处理。
公开分享和其他接口、平台协议范围见 [接入条件与验收](INTEGRATION_REQUIREMENTS.md)。
人工回复保持独立面板；临时切到前台再恢复不等于无前台依赖或锁屏后台发送。
