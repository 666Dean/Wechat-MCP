# 原账号自动回复：接入条件与验收

审查日期：2026-10-13。本文定义接入和验收要求，不代表腾讯授权或法律意见。
目标是以用户原账号向既有私聊回复；独立机器人或公众号不得替代该目标的验收。

## 平台许可与公开入口

[腾讯微信软件许可及服务协议](https://weixin.qq.com/cgi-bin/readtemplate?lang=zh_CN&t=weixin_agreement&s=default)

第三方挂接（8.2.1.4）、未授权第三方自动化及界面/数据访问（8.2.1.6）、
规避安全保护（8.2.1.7）作出限制。用户授权、系统权限和开源代码许可证，
分别不能代替平台许可或适用例外审查；技术上可调用也不等于可公开运营。
这些是协议层面的限制，本文不据此断言某项行为构成违法。
现有读取功能同样不能仅因只读或本地处理就被认定已获得平台许可。

公开资料复核结果：

| 路径 | 当前证据 | 原账号私聊结论 |
| --- | --- | --- |
| Mac 官方分享服务 | 本机文件输入可移交原版选择器；纯文本输入不支持 | 尚无稳定收件人、精确文本提交或发送证明 |
| 私聊窗口 OCR | 指定窗口经原始系统选择器返回透明帧 | 不能验证输入、正文或目标；不得扩大捕获范围规避保护 |
| iLink | 腾讯公开 Bot 协议包含文本发送方法、Bot token 和会话上下文 | 独立机器人身份；仅备用，不映射成原账号私聊 |
| 公众号回复 | 腾讯公开的发布流程要求公众号身份授权 | 公众号渠道，不是用户原账号 |
| 客户端私有函数 | 版本指纹、静态候选或文件句柄仅是局部线索 | 未验证完整请求、生命周期及身份，也未取得接入许可 |

## 原账号合作接口所需信息

向平台申请接入或进行适用例外审查时，应明确以下范围。本文只是准备材料，
不会自动向平台或第三方发送申请，也不包含真实联系人、密钥或聊天正文。

1. 是否允许 Mac/Windows 原账号第三方读取、自动回复，以及公开分发、商业使用的范围。
2. 账号认证、收件人稳定 ID 的命名空间与校验方法；显示名称不能作为唯一发送身份。
3. 文本请求字段、长度/格式约束、运行线程、对象所有权和取消语义。
4. 请求去重、限流、账号失效和收件人变化的处理；发送回执与送达回执如何区分。
5. 后台执行是否受支持，以及系统锁屏、客户端重启、会话切换后的行为。
6. 最小权限、凭证保存、撤销和审计要求；哪些信息允许本地处理或向模型披露。

没有上述依据时，不通过重签客户端、注入、令牌截取/重放或修改捕获保护补齐入口。

## 三项独立条件

平台许可/例外依据、后端技术验收、所有者精确授权须分别满足，互不替代。
`send_available` 仅表示适配器技术能力，不是法律结论、平台许可或用户授权。
App/MCP 不签发权限；所有者批准仍绑定账号、收件人、正文、来源、有效期和次数。

原始草稿发送与回复任务提交使用同一技术可用性检查，只接受 UI/hybrid 模式和
严格布尔值 `send_available=True`。异常、缺失字段、字符串和数值不能打开入口；
未资格后端在创建发送任务前拒绝。提交时再次检查当前策略和能力，能力变化不得
调用发送适配器。进入提交阶段后的失败保留 Unknown，不自动重试。
这些检查只收紧入口，没有启用原版 Mac 自动发送，也不改变 SDK 的安全语义。

验收必须分别证明：指定原账号和收件人、精确正文只发送一次、独立数据库记录核对、
后台条件下的相同行为、撤权/目标变化/能力失效时停止。移交回调、截图、模拟发送、
数据库出现相同文本均不能单独作为对端送达证明。人工回复面板继续独立保留。

OpenAI 的[计算机使用指南](https://developers.openai.com/api/docs/guides/tools-computer-use)
支持截图与界面操作，并要求范围限制、外部内容不可信、用户控制和实际结果核验。
不应把 OCR 本身描述为被一概禁止；同样不能以一般计算机使用能力替代平台许可。
