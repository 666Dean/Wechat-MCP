# Mac 原账号回复：替代渠道资格

平台许可、技术能力与所有者授权须独立满足；当前没有原账号自动回复的合格接入。
公开入口与合作接口要求见 [接入条件与验收](INTEGRATION_REQUIREMENTS.md)。
OCR 本身不是一概禁止，但透明帧不能用于可靠发送，也不能绕过保护取得画面。

## 2026-10-13 捕获恢复与官方文件分享实测

本轮独立 AppKit 合成窗口在原配置和显式 BGRA 配置下均能截图、OCR；
开发对照工具取得 1360×704、2 行文字且已知文字匹配。此前通用 `-3811`
未复现，但没有确认根因，不能声称配置变更修复了系统或保证长期捕获。
没有重置 TCC、修改客户端共享属性、注入或切换过滤器规避排除。

腾讯官方分享入口实际取得 1360×740 / 8 行 OCR；“发送给朋友”移交到
原版“微信发送给”选择器，取得 1488×1120 / 33 行 OCR、4028 个不透明采样。
同一服务的公开 `canPerform(withItems:)` 在本机结果为：

| 输入 | 本机支持 |
| --- | --- |
| 本地文件 URL | 是 |
| NSString 纯文本 | 否 |
| NSAttributedString 富文本 | 否 |
| 文件 URL 与纯文本组合 | 否 |

这只是类型资格和 UI 移交，不证明文件已发出，也不证明文本回复可用。
没有预填未经验证的 recipients、选择真实收件人或执行发送。
客户端打开了三个已配置消息库，是进程与数据库关联证据，不能代替完整账号/收件人资格。

指定真实独立私聊经所有者认证、精确一次授权和 Apple 选择后，使用原始
单窗口 filter 返回 598×640 全透明帧，OCR 0 行、不透明采样 0；
FailedSafe、审计有效、读取撤权、图片未留存、正文未披露。
因此合成与选择器捕获恢复没有解决私聊的输入/草稿见证，自动发送、读回和后台写入未通过。
旧共享标志不是现代保护的充分证据；失败后不改变属性、切换捕获范围或盲用坐标。

开发者可构建并显式运行仅捕获自身窗口的对照（不会进入产品 UI）：

```sh
python scripts/build_axr.py --mac-selection-probe
.local-private/build/AXR/axr-mac-capture-control --self-test
```

需要现有系统录屏授权。该工具不会自动申请权限、捕获其他应用、保存图像或运行微信写入。
输出只有已知合成文字匹配、尺寸和错误码；失败返回非零，不是原账号能力验收。

## 2026-10-13 较早观察（捕获复测前的历史记录）

使用 Apple NSSharingServicePicker 的实际菜单及公开 perform API，合成文件输入下已出现
微信服务并启动腾讯签名的官方分享扩展。没有修改、重签微信或注入进程；没有选择
真实收件人或调用提交。正式宿主窗口标题为微信分享界面，AX 角色可观察；角色包含
文本区域不等于已得到可写聊天输入、账号或稳定收件人身份。

本地所有者认证后的初始化观察限账号/联系人/输入控件，不读既有聊天正文；原始标签
与详细记录保持本地。一次宿主已无窗口的空观察不算成功。服务出现和进程启动仍不证明
纯文本支持、原账号身份、指定私聊发送、独立数据库读回或后台资格。

历史旧 NSSharingService 枚举未发现微信，不能再外推为现代选择器不可用。后续仍必须
核实稳定目标与精确载荷，缺失时不得启用生产发送；当前 automatic send 未通过。

保持服务对象与来源窗口后，单帧捕获仍在 screenshot 阶段返回 SCStreamErrorDomain
`-3811`；同一个宿主的合成窗口同样失败。未取得图像或 OCR 文字，不能用该错误
证明微信有意阻断，亦不能把它当作已验证的全局系统故障。部分 AX 根节点形状无效，
通用 helper 按安全规则拒绝，不能把原始角色计数认定为可靠聊天/输入控件。

## 2026-10-12 历史复核（人工提交阶段）

本轮人工提交要求保持。新增的是明确 opt-in 的非关键词入站任务和自动草稿，不把它称为 Agent 自动发送。当前 Mac 锁屏，UI 结构观察不能外推解锁后的资格；SDK 修正循环/无效窗口根后需要重新验收。

重新核对 [WeChatTool 官方说明](https://github.com/WeChatTool/WeChatTool)：其可选 accessibility 功能针对修改并本地签名的独立副本，公开支持画像为 4.1.15 / 270099，且明确未证明实际自动化行为。本机为 270134，不能据其静态检查调用发送或替换本机客户端。本轮没有运行安装器、创建副本、重新登录或修改微信。

[wechat-use 官方仓库](https://github.com/leeguooooo/wechat-use) 仍以独立 4.1.9 副本为持续适配目标；[许可](https://github.com/leeguooooo/wechat-use/blob/main/LICENSE) 限制商业用途。它不能直接当作本项目可整合的本机原账号发送通道。原账号自动发送继续要求运行账号/收件人身份、当前请求 ABI 与生命周期、精确授权及独立记录观察；缺失时保持关闭。

2026-10-11。验收目标仍是主人授权的两个既有私聊；没有用机器人会话或文件传输助手替代本人内部 ID 私聊。公开记录不含真实身份、正文、凭据或截图。

当前原版 270134 的实际离线调用链和固定样本校验见 [原生适配记录](MAC_NATIVE_270134.md)。已经定位任务/序列化候选；尚缺上层请求 ABI 与运行中账号/收件人身份，不开放发送。

[协议](https://github.com/Tencent/openclaw-weixin/blob/c6643f6f0ac03574eb126f2d69569ea4267cc3c6/docs/protocol_zh_CN.md) 使用独立 Bot token 和 iLink 身份，扫码为 bot_type=3；发送使用机器人消息及 context_token。
仓库说明区分客户端行为与服务端契约，不能将可选字段当作服务端可用承诺。

已审查代码没有证明能枚举或使用原账号好友的 WCDB 内部 ID，也没有证明可直接操作原账号的两个既有私聊。因此没有启动扫码、保存 Bot 凭据或接入官方机器人运行服务；不能用该渠道宣称本次原账号闭环通过。

## 厂商分享扩展

已安装腾讯客户端含官方 Share Extension；bundle 中的 URL scheme 不能证明提供按私聊 ID 发送文本的 API。
本机 NSSharingService 的纯文本候选枚举没有微信；该旧 API 的一次枚举不证明现代分享菜单或厂商扩展不可用。
没有调用 perform、转发正文、选择联系人或执行真实发送。分享流程仍缺少经过验证的账号/唯一私聊身份和完成见证。

进一步检查 SovietExtension 的发送运行时解析器：具体 SendMsgCGI 路径仅允许旧 build 268853；
269079 的独立转发 ABI 也有版本/UUID 条件，不能把旧地址当作本机能力。

后续原生发送适配需当前版本/架构/厂商签名/模块身份与 ABI 匹配、独立账户/收件人见证、
精确正文授权、单次提交和本地记录观察；未知结果不得盲重发。不把历史 hook、机器人身份或数据库写入当作发送成功。

## 继续排除表面可用的替代方案

其捕获流程先包含应用、再更新为窗口过滤器；没有运行该代码或采用其捕获路线。
它不提供按原账号稳定收件人 ID 调用的非 OCR 发送接口，不能覆盖本机当前的空画面问题。

本机只读检查当前安装包：核心位于 Resources 下的 universal wechat.dylib，Frameworks 下同名文件是较小的加载层。
核心导出符号检查未找到可直接使用的 SendMsg/Req2Buf/openChat 入口；内部 Req2Buf 字符串不能证明 ABI 或正确地址。
针对聊天 URL 的静态检查没有得到可验证契约，没有向未知 URL 传递联系人或调用内部函数。
这些检查只读取已安装程序代码，没有访问进程消息、会话正文或凭据，也没有给 Agent 发放新的数据权限。

## 标准升级与系统选择器

[Homebrew cask 元数据](https://formulae.brew.sh/cask/wechat) 对应腾讯官方下载的 4.1.15.54 / 270134。下载包 SHA256 匹配，腾讯 Developer ID/Team 签名严格校验及 Gatekeeper 评估通过。
主人正常退出 270102 后完成标准升级；保留原签名应用副本，新版未重签名、未注入、无实验启动参数。进入既有账号后主聊天 AX 仍无输入节点，工具截图仍白屏。
应用副本不是账号数据迁移的完整回滚，不将升级后的数据可降级作为已验证承诺。

Apple 官方单窗口选择器的元数据探针已在本机运行：主人选的是主窗口，返回单窗口/PID/bundle 校验成功；未启动捕获，不保存图像，不执行 OCR 或输入。
探针关闭后不会将结果持久化为会话绑定或授予读取/发送权限。SDK 保留 legacy sharing=0 的自动捕获拒绝检查。
[Apple 对旧共享常量的说明](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none) 表明数值本身不能证明现代保护状态或可捕获性。

当前可证实的是 WCDB 读取与合成输入/OCR 路径；原账号真实发送、发送后读回及后台写入仍未通过。
下一项必要资格是同时取得官方可读取的目标身份、可检查的空草稿/精确正文及单次提交见证；缺失时不能进入真实发送测试。

## 所有者单帧与合成对照补充

本轮显式本地所有者入口经新的 OS 认证、精确单次授权及主人选择后，用原始 Apple 单窗口 filter 实际调用截图和本地 Vision。
两个已指定独立私聊均返回 598×640 帧，OCR 0 行、0 个不透明采样；当前空帧判为 FailedSafe，不能称为读取通过。
同一路径纯合成窗口失焦时成功：1280×1024、4 行/67 字节、4072 个不透明采样，审计有效。
这验证实现可捕获合成内容，但不确定微信内部的限制原因，不修改或绕过隐私保护。
无图片落盘、模型正文披露或真实发送；操作结束撤权及逻辑清理。窗口选择不证明内部 ID、草稿或发送资格。
合成前两次等待超时不算成功；历史元数据或旧捕获事务 Completed 不等于可用内容验收。
微信失焦下空帧不算后台读取通过，发送/发送后读回/后台写入/多日运行仍未通过。
请求格式、安全边界及复现见 [MAC_REPLY.md](MAC_REPLY.md)。
