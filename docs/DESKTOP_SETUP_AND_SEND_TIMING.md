# 首次设置、完全访问与发送时机

## 首次设置

Qt 桌面首次打开时显示四步向导，也可从设置 → 连接与外观 → 设置向导重新进入。
连接本地组件、核对系统权限、选择 Codex 对话、批准微信范围后，向导分别检查服务、
数据访问、设备控制、回复助理、对话绑定、范围授权和真实 MCP 初始化/工具调用。
七项实际检查全部通过才可完成，完成前再次复核；演示状态或页面勾选不能替代检查。
向导不会为了验收自动读取聊天正文或发送消息。

Developer Preview dp2 内置通用签名 AXR 组件，无需另行编译账号安装包。向导选择
本人微信数据文件夹、核对稳定 ID，并导入合法持有的原始密钥缓存或已有 AXR 索引。
桌面只准备路径、代际和文件指纹；原生 Authority 在本人认证后校验/导入，不向
Python 或模型返回密钥。没有合法数据凭据时不能完成微信连接，不提供提取入口。

Codex 按官方方式安装并通过浏览器登录。确认后只修改 `wechat_axr` MCP 配置，保留
其他设置；完成检查要求实际注册且可初始化新前端。App 不再分发供应方 Codex App，
本机安装验证并固定用户自己的签名程序。系统权限和硬件签名仍由本人完成，取消不
恢复旧授权；已有安装不会重新初始化。详细格式见[独立服务部署](INDEPENDENT_SERVICE.md)。

## 完全访问

从设置或输入框权限菜单选择完全访问，先阅读风险确认，再核对精确范围并完成
本机签名。完全访问包含本人私聊的任务入口，因此必须有有效 Codex 绑定，并将
本人稳定 ID 加入范围；界面自动保留该必需目标，无法误取消。缺少绑定时给出明确
入口，在满足条件前禁止提交，而不是静默退回普通自动回复。

打开菜单和取消确认不改变原权限。真正提交时先停止旧范围，再请求新签名；签名
取消后保持停止。完全访问只允许本人 `/agent` 将任务交给绑定对话，普通联系人的
文字仍进入无工具的隔离回复 Agent，敏感操作继续由原工具审批机制确认。

## 发送时机

| 选项 | 行为 |
| --- | --- |
| 默认：立即切换微信发送 | 前台自动选聊、精确核对后单次提交 |
| 空闲 15 秒后发送 | 没有近期键鼠活动时才开始一笔发送，随后会将微信置前 |
| 仅微信在前台且空闲时 | 等待用户正常切回微信并空闲，不主动抢占其他应用 |

时机和空闲阈值写入所有者签署的范围，模型不能自行改变。活动状态不可用时等待，
不把未知状态当空闲；等待期间不输入、不按发送、不消耗发送次数。停止撤销待发送
任务，排队超过自身期限便安全结束，服务重启不恢复旧队列。自动回复和 MCP 主动
发送使用同一个队列，合批推理保留来源并为已排队发送预留额度。

空闲判定在整笔发送开始时执行。后续中转选聊使用 authority 密封的继续标记，不因
本次模拟按键重置系统计时而误停；仍要求微信保持前台、固定窗口、精确新鲜收件人
及输入比对。最终提交仍是新鲜单次认领。它不是与用户同时编辑微信的并发保证。

## 后台发送的实际边界

当前设备没有通过原号私聊的无前台发送验收，产品不提供该选项。受限研究路径
只接受额外签名的短时、少次数试验，必须保持前台不变，并有精确数据库记录才能
记录设备资格；从未因合成窗口成功或用户口头授权直接宣称可用。

本轮公开定向按键对照显示，模拟按键会重置系统活动计时，并可能激活目标窗口。
真实后台尝试在活动保护处停止，保留 Unknown，未重试。不能把定向 PID 当作
后台不打扰保证。当前建议使用“仅微信在前台且空闲时”。键盘路径仍临时使用系统
剪贴板，只在自己的剪贴板 epoch 未被用户改变时恢复内存备份。

打开访问范围/发送时机设置时，界面直接解释当前策略是否会置前微信，并说明
无前台发送的限制。未通过后台验收的设备不会出现一个看似可用的后台开关。
临时保存剪贴板并不能让微信在后台可靠接收输入，也不能保证与用户复制操作并发。

实现只使用公开的 [定向事件接口](https://developer.apple.com/documentation/coregraphics/cgevent/posttopid(_:))
及[活动时长接口](https://developer.apple.com/documentation/coregraphics/cgeventsource/secondssincelasteventtype(_:eventtype:))；
不采集按键正文，不截图、不注入、不更改微信的窗口隐私属性。

应用图标为仓库内矢量图，构建时导出标准尺寸 ICNS，并应用到启动器、窗口和 Dock。
本机 Qt 验证与 Windows 实机界面资格分开记录。当前设备结果见 [状态页](STATUS.md)。
