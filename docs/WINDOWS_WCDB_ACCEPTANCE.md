## 实机检查步骤与结果

1. 使用原有当前用户 DPAPI 凭据，在内存中按各分库 salt 和显式 password 语义校验首页 HMAC。三个分库均匹配；没有重新获取密钥或写入新的凭据。
2. 以 READONLY / mode=ro 打开原消息库，开启 query_only；每个分库页在表结构读取前 BEGIN，消息与 Name2Id 查询共享只读事务，结束关闭连接。
3. 执行无正文关键词过滤的升序有界查询，单页扫描额度 20。媒体等非文本记录不输出正文，文本严格 UTF-8/Zstd 解码；方向只按精确绑定及 Name2Id 解析。
4. 重复读取同一页，再使用返回游标读取一条后续记录；核对整页内容、引用、方向及连接释放。
5. 保持原绑定再进行 10 次短时重复查询，并仅查时间/方向元数据，核对该私聊的最新入站、出站是否早于测试窗口。主人指出账号最新发出时间与该私聊不同后，另对账号范围执行有界时间/方向聚合，仍不读取其他会话正文。

| 检查 | 实测结果 |
| --- | --- |
| 页密钥校验 | 三个分库全部通过；证明已有凭据对这些库可用，不证明自动取钥或升级后持续可用 |
| 初始有界页 | 扫描 20 条记录，返回 17 条文本；对方 7 条、本人 10 条，全部正文解码和方向校验通过 |
| 重复读取 | 引用一致，完整返回页相等 |
| 后续游标 | 初始页 has_more=true；后续页实际扫描并返回 1 条文本，与初始页引用无交集，不是空页的平凡通过 |
| 连接清理 | 每页查询后连接集合为空，没有保留跨页事务 |
| 短时观察 | 34.5 秒内额外查询 10 次，0 错误、0 变化页；每次读取后连接释放 |

| 写入和披露 | 没有微信发送、消息编辑、正文落盘、MCP 正文披露、owner state 初始化或新权限签发；原有业务监听/草稿队列未启用 |

## 合成验证单独记录

合成加密 WAL 使用同一 SQLite3mc 引擎：读事务内看不到 writer 的后续提交；结束读事务后可见新提交；writer 未提交记录不可见；只读连接对一个未占用主键的 INSERT 明确抛出 ReadOnlyError。合成正文不出现在 WAL 明文中，连接关闭后临时夹具清理。这不等于在真实微信中制造和观察了新消息。

本机 Python 3.12 全量发现 124 项，115 项执行通过、9 项因可选原生 AXR 缺失跳过。[双平台 CI](https://github.com/666Dean/wechat-codex-mcp/actions/runs/38405728110) 对被测代码已完成并通过，覆盖原生构建/CTest/回归；CI 和合成夹具均不替代 Windows 微信设备验收。

## 尚未通过的范围

- 前轮的正式 SQLCipher C ABI、原生 SDK/helper 限制已由本页顶部本机验证更新；Windows Hello 本人认证、真实数据 stdio MCP 与人工回信闭环仍未验收。
- 绑定测试私聊在观察窗口没有新入站，因此新入站增量发现、实时延迟、持续写 WAL、后台失焦/最小化、锁屏和重启均未验证；不能把该私聊的结果外推为整个账号没有新记录。
- 本轮主要查询的是升序首个有界页，不是完整聊天历史；最新时间元数据另行核对，不能把旧页稳定等同于最新消息增量正常。
- 单分库单页快照不是跨分库同一时刻快照；历史补录、压缩字典、密钥变化、大库性能及长期运行仍需独立验证。
- legacy DLL 的 -100 没有修复；本轮未授予或执行真实发送。
